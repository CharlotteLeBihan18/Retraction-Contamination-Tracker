# Index benchmark (PROFILE before and after)

Generated by `python -m scripts.benchmark_index` on a graph of 9354 papers.
Values used: DOI `10.1002/14651858.cd001724.pub2` (the most cited retracted paper), OpenAlex id `W1998908303` (the citing paper with the most citations to retracted papers), year 2023 (the most common year).
Time is the median of 50 runs after 3 warm-up runs, measured from Python, so it includes the network round trip. Database hits do not depend on the machine.

How to read the plan: `NodeIndexSeek` / `NodeUniqueIndexSeek` jump straight to the matching papers through the index; `NodeByLabelScan` reads every node of a label and `Filter` throws away the ones that do not match.

## paper_doi (unique constraint on Paper.doi)

| Query | Index | Plan (from the leaves up) | DB hits | Median time |
| --- | --- | --- | --- | --- |
| Find a paper by DOI | before (without) | NodeByLabelScan (p:Paper) → Filter → Projection → ProduceResults | 18,710 | 20.81 ms |
| Direct citers of a retracted paper (start of /contamination) | before (without) | NodeByLabelScan (r:Retracted) → Filter → Expand(All) → Filter → EagerAggregation → ProduceResults | 2,493 | 10.74 ms |
| Find a paper by DOI | after (with) | NodeUniqueIndexSeek (UNIQUE p:Paper(doi) WHERE doi = $doi) → Projection → ProduceResults | 3 | 6.91 ms |
| Direct citers of a retracted paper (start of /contamination) | after (with) | NodeUniqueIndexSeek (UNIQUE r:Paper(doi) WHERE doi = $doi) → Filter → Expand(All) → Filter → EagerAggregation → ProduceResults | 1,127 | 7.79 ms |

- Find a paper by DOI: **6,237x fewer database hits** with the index.
- Direct citers of a retracted paper (start of /contamination): **2x fewer database hits** with the index.

Why the two gains are so different: without the index, finding a paper by DOI has to read every `Paper` node, so the index saves almost all the work. The direct-citers query starts from the `:Retracted` label, so even without the index Neo4j only scans the retracted papers, which is already a small scan. Most of its remaining hits come from walking the citations, and no index can skip that part.

## paper_openalex_id (unique constraint on Paper.openalex_id)

| Query | Index | Plan (from the leaves up) | DB hits | Median time |
| --- | --- | --- | --- | --- |
| Find a paper by OpenAlex id | before (without) | NodeByLabelScan (p:Paper) → Filter → Projection → ProduceResults | 18,710 | 13.53 ms |
| Citations of one citing paper (how the loader links them) | before (without) | IntersectionNodeByLabelsScan (anon_0:Paper&Retracted) → Expand(All) → Filter → EagerAggregation → ProduceResults | 24,915 | 19.78 ms |
| Find a paper by OpenAlex id | after (with) | NodeUniqueIndexSeek (UNIQUE p:Paper(openalex_id) WHERE openalex_id = $openalex_id) → Projection → ProduceResults | 3 | 6.65 ms |
| Citations of one citing paper (how the loader links them) | after (with) | NodeUniqueIndexSeek (UNIQUE a:Paper(openalex_id) WHERE openalex_id = $openalex_id) → Expand(All) → Filter → EagerAggregation → ProduceResults | 101 | 6.6 ms |

- Find a paper by OpenAlex id: **6,237x fewer database hits** with the index.
- Citations of one citing paper (how the loader links them): **247x fewer database hits** with the index.

This is the key the loader depends on most: citing papers (some of them have no DOI) and every citation to a retracted paper are matched by OpenAlex id, so without it each of the thousands of citations would scan all the papers.
